# Сопровождение upstream

## Репозитории

- upstream: zai-org/ZCode.
- origin: logout2d/ZCode.

## Ветки

- main — зеркало официального upstream/main.
- custom/main — собственная стабильная ветка.
- task/* — отдельные задачи разработки.
- update/* — интеграция официальных обновлений.

## Правила

1. Не добавлять собственные исправления в main.
2. Обновлять main только fast-forward.
3. Интегрировать upstream через отдельную ветку.
4. Не переписывать опубликованную историю.
5. Не отправлять изменения непосредственно в upstream.
6. Не отключать штатные проверки Husky.
7. Сохранять архитектурные правила upstream.
8. Проверять обновления до установки.
9. Не прерывать работающие задачи агентов.

## Первая публикация ветки

Публичный upstream не содержит origin/staging.
Для первой публикации допустимо явно передать
подтверждённую базу через ZCODE_AFFECTED_TEST_BASE.

Например, для первой публикации custom/main:

    ZCODE_AFFECTED_TEST_BASE=origin/main git push -u origin custom/main

При последующих публикациях существующей ветки
используется штатная обработка удалённого SHA.

Не устанавливать переменную базовой ветки глобально.
Для новых task/* выбирать фактическую базу задачи.
